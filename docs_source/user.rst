API пользователей
=================

Регистрация и вход
------------------

* ``POST /api/v1/users`` принимает ``login`` (email), ``password`` и необязательный
  ``system_id``. Без системного ID создаёт аккаунт с ролью ``customer``. С системным
  ID привязывает email и пароль к существующему аккаунту. Ответ ``201``. Неизвестный
  системный ID даёт ``401``, занятый email или уже привязанные данные — ``409``.
* ``POST /api/v1/users/id`` создаёт аккаунт с новым UUIDv4 и ролью ``customer``.
  Тело запроса не требуется. Ответ ``201``.
* ``POST /api/v1/sessions`` принимает ``login`` и ``password``, а
  ``POST /api/v1/sessions/id`` принимает ``system_id`` любого аккаунта.
  Успешный вход возвращает ``200``, неверные данные — ``401``.
  На каждый маршрут входа действует лимит пять запросов в минуту на IP.
  При превышении API возвращает ``429`` с заголовком ``Retry-After``.

При регистрации или входе ответ содержит ``access_token``, ``refresh_token``
и ``system_id``.

Обновление токенов
------------------

``POST /api/v1/tokens/refresh`` принимает ``refresh_token`` в теле запроса.
Ответ ``200`` содержит новый access-токен и новый refresh-токен. Обмен делает
предыдущий refresh недействительным и сохраняет исходный срок сессии. Просроченный,
неизвестный или уже использованный токен даёт ``401``.
Если Redis недоступен, выдача или обновление пары токенов возвращает ``503``.

Роли и сотрудники
-----------------

Оба маршрута принимают заголовок ``Authorization: Bearer <access_token>``.
Без действительного токена API возвращает ``401``.

* ``GET /api/v1/roles`` читает текущую роль пользователя из БД. Ответ ``200``
  содержит поле ``role`` со значением ``admin``, ``marshal`` или ``customer``.
* ``POST /api/v1/users/employee`` доступен администратору и принимает
  ``login``, ``password`` и ``role``. Для роли допустимы ``admin`` и ``marshal``.
  Написание ``marshall`` сохраняется как ``marshal``. Сервер генерирует системный
  ID и возвращает ``201`` с полями ``id`` и ``role``. Для пользователя без роли
  администратора ответ ``403``, при занятом email — ``409``.
